\section{Постановка задачи обхода разреженных графов}

Настоящая работа посвящена исследованию вычислительной эффективности алгоритмов обхода графов в ширину (\foreignlanguage{english}{Breadth-First Search, BFS}) при обработке больших разреженных структур. Скорость выполнения этих алгоритмов определяет общую производительность современных систем интеллектуального анализа данных, социальных сетей и поисковых движков.

\textbf{Цель работы}~--- экспериментальное исследование и сравнительный анализ производительности классического последовательного (на базе формата \texttt{CSR}~--- \foreignlanguage{english}{Compressed Sparse Row}) и линейно-алгебраического (в базисе интерфейса \texttt{GraphBLAS}) подходов к реализации обхода графа в ширину на различных типах топологий разреженных данных для выявления оптимальных границ их применимости.

Для достижения поставленной цели решены следующие \textbf{задачи}:
\begin{itemize}
    \item Реализовать последовательные и линейно-алгебраические алгоритмы обхода в ширину.
    \item Разработать независимую подсистему автоматизированного тестирования инвариантов.
    \item Провести экспериментальные замеры времени выполнения на реальных графах.
    \item Выявить и обосновать топологические границы применимости подходов.
\end{itemize}

\subsection{Варианты обхода в ширину}

В рамках настоящего исследования рассматриваются два вычислительных варианта алгоритма обхода в ширину (\foreignlanguage{english}{Breadth-First Search, BFS}) для невзвешенных структур:
\begin{itemize}
    \item \texttt{parent-BFS} --- классический поиск из одного корня с фиксацией дерева предков в массиве \texttt{parent} для восстановления кратчайших путей.
    \item \texttt{multisource BFS} --- параллельный запуск волн обхода из фиксированного множества начальных источников для анализа близости групп центров графа.
\end{itemize}

\subsection{Формат представления графов CSR}

Для реализации последовательных алгоритмов разработан формат сжатого хранения строк (\foreignlanguage{english}{Compressed Sparse Row, CSR}). Он исключает хранение нулевых элементов и сокращает сложность по памяти до $O(|V| + |E|)$ за счет использования двух плоских массивов:
\begin{itemize}
    \item \texttt{row\_ptr} --- массив смещений размера $|V| + 1$, фиксирующий границы списков смежности для каждой вершины в общем пуле данных.
    \item \texttt{col\_idx} --- массив индексов размера $|E|$, последовательно хранящий числовые идентификаторы смежных узлов.
    \item Массив значений ребер --- для исследуемых невзвешенных графов (\texttt{pattern}-матрицы) полностью исключен из структуры и не занимает физическую память.
\end{itemize}
Такое линейное представление минимизирует накладные расходы на адресацию ячеек и гарантирует высокую локальность кэш-памяти процессора при последовательном чтении соседей.

\section{Реализация алгоритмов и подсистемы верификации}

В данном разделе приводится описание архитектуры разработанного программного комплекса, принципов интеграции вычислительного ядра с интерфейсом \texttt{GraphBLAS}, а также логики автоматизированных тестов.

\subsection{Интеграция с линейно-алгебраическим интерфейсом SuiteSparse:GraphBLAS}

Матрично-векторная версия алгоритма обхода реализована в модуле \texttt{graphblas\_bfs.c}. Перенос топологии графа во внутреннюю структуру библиотеки осуществляется низкоуровневой функцией \texttt{GxB\_Matrix\_import\_CSR}. Архитектурной особенностью разработанного загрузчика графов является добавление новых ребер в начало связных списков смежности, что формирует массивы \texttt{col\_idx} в порядке убывания индексов вершин внутри каждой строки. Для корректной интеграции с библиотекой флаг \texttt{jumbled} при импорте устанавливается в значение \texttt{true}. Это сигнализирует ядру \texttt{SuiteSparse} о необходимости внутренней сортировки и перегруппировки индексов столбцов перед выполнением вычислений, что гарантирует математическую корректность последующих проходов.

Низкоуровневые операции управления очередью в среде \texttt{GraphBLAS} заменены на линейно-алгебраические абстракции над разреженными структурами:
\begin{itemize}
    \item \textbf{Вектор фронта (\texttt{frontier})} --- разреженный булев вектор, детерминирующий присутствие вершин на текущей линии обхода графа.
    \item \textbf{Операция шага (\texttt{GrB\_vxm})} --- векторно-матричное умножение вектора фронта на матрицу смежности $A$ на базе логического полукольца \texttt{g\_lor\_land\_semiring} (или \texttt{GrB\_mxm} для мультисоурс-реализации).
    \item \textbf{Управление историей посещений} --- применение инвертированной маски вектора \texttt{visited} с дескриптором \texttt{g\_desc\_visited\_comp\_replace} для отсечения пройденных вершин и обновления состояния.
\end{itemize}

\subsection{Изоляция измеряемых факторов и интеграция эталона}

Для обеспечения методологической чистоты эксперимента базовые алгоритмы обхода были разработаны самостоятельно непосредственно поверх структур \texttt{CSR} и базового ядра библиотеки \texttt{SuiteSparse:GraphBLAS}. Использование высокоуровневых фреймворков, таких как библиотека \texttt{LAGraph}~\cite{lagraph}, было намеренно исключено. Она содержит внутренние динамические эвристики, включая направление-оптимизированный поиск (\foreignlanguage{english}{direction-optimizing BFS}) и автоматическое переключение форматов векторов фронта. Включение таких факторов в контур тестирования привело бы к смешению измеряемых параметров, делая невозможным корректное сопоставление базовой эффективности матрично-векторной концепции с последовательным обходом. Самостоятельная реализация гарантирует строго эквивалентные стартовые условия запуска.

Для проведения объективной внешней верификации скоростных показателей в общую систему сборки \texttt{CMake} был интегрирован независимый эталон --- алгоритм последовательного обхода из библиотеки \texttt{Boost Graph Library} (\texttt{BGL})~\cite{boost-graph}. Он вызывается изолированно внутри основного цикла бенчмарка и выполняет роль глобального \foreignlanguage{english}{baseline}-ориентира. По сравнению с низкоуровневым С-кодом библиотека \texttt{BGL} демонстрирует меньшую производительность из-за двух архитектурных факторов:
\begin{itemize}
    \item Высокий уровень абстракции механизмов обратного вызова (\foreignlanguage{english}{BFS visitors}) и итераторов создает значительные накладные расходы на диспетчеризацию вызовов внутри итерационного цикла обхода, ухудшая конвейеризацию инструкций процессора.
    \item Применение по умолчанию тяжелых 64-битных типов данных (\texttt{size\_t}) для индексов вершин удваивает объём считываемых данных, увеличивая нагрузку на шину памяти и снижая локальность процессорного кэша первого и второго уровней (\texttt{L1/L2 cache misses}).
\end{itemize}

\subsection{Архитектура автоматизированного тестирования}

Для обеспечения надежности программного кода разработана подсистема автоматических тестов --- каталог \texttt{src/tests}, управляемый встроенным в \texttt{CMake} механизмом \texttt{enable\_testing()}. В отладочной конфигурации (\texttt{Debug}) проверка корректности работы функций опирается на системные макросы \texttt{assert(...)} и тестовый базис в виде жестко зашитого в памяти эталонного графа из 5 вершин, генерируемого в файле \texttt{test\_utils.c}. Валидация кодовой базы разделена на три этапа:
\begin{itemize}
    \item \textbf{Проверка связности дерева предков (\texttt{test\_classic\_bfs.c}):} валидация корректности корня и проверка отсутствия циклических петель в структуре путей.
    \item \textbf{Перекрестное побитовое сравнение (\texttt{test\_comparison.c}):} поэлементная верификация совпадения векторов уровней классического BFS и вычислений в GraphBLAS.
    \item \textbf{Тестирование мультисоурсного инварианта (\texttt{test\_graphblas\_bfs.c}):} проверка математического закона \texttt{level[i] <= level\_single[i]}~--- свойство монотонности при расширении множества источников.
\end{itemize}

Анализ экспериментальных данных позволяет выявить четкие границы применимости подходов, продиктованные \textbf{структурой связности (топологией)} исследуемых графов:
\begin{itemize}
    \item \textbf{Безмасштабные сети с малым диаметром (Power-law graphs)}~--- \texttt{com-Orkut}, \texttt{soc-LiveJournal1}. Данные структуры характеризуются наличием вершин-концентраторов («хабов») с высокой степенью фильтрации. При обходе в ширину это вызывает лавинообразное расширение фронта уже на первых итерациях. В данных условиях линейно-алгебраический подход демонстрирует максимальную эффективность, опережая последовательный С-кодовый аналог до~3,91~раза. Высокая плотность текущего фронта позволяет внутренним механизмам \texttt{SuiteSparse} эффективно задействовать параллелизм при перемножении матриц. Основным ограничивающим фактором здесь выступает пропускная способность подсистемы памяти (\textit{Memory Bandwidth Bound}), а не вычислительная сложность процессора.

    \item \textbf{Разреженные структуры с большим диаметром (Дорожные сети)}~--- \texttt{roadNet-CA}, \texttt{road\_usa}. Для графов данного типа характерны низкая средняя степень вершин и протяженные цепочечные топологии. При одиночном поиске (\texttt{GB-L}) \texttt{GraphBLAS} существенно уступает классическому алгоритму на C из-за высоких накладных расходов библиотеки на управление масками и динамическими структурами разреженных векторов фронтов на каждой из тысяч последовательных итераций.

    Однако в режиме мультипоиска (\texttt{GB-M}) на графе \texttt{road\_usa} наблюдается выраженное падение времени выполнения до~36194~мкс по сравнению с одиночным прогоном. Данный эффект обусловлен тем, что при одновременном старте из нескольких удаленных источников разреженные волновые фронты локализуются в изолированных или тупиковых подграфах дорожной сети. Это приводит к значительному сокращению эффективного диаметра обхода для каждого отдельного потока и досрочной терминации циклов полукольца, что частично нивелирует накладные расходы алгоритма.

    \item \textbf{Иерархические ориентированные структуры (Сети цитирований и веб-ссылки)}~--- \texttt{cit-Patents}, \texttt{web-Google}. Облагают высокой анизотропией (направленностью) связей и выраженной кластеризацией. Последовательный код на C работает стабильнее решений на \texttt{GraphBLAS} (до~25,4~раза на \texttt{cit-Patents}). Причиной неэффективности линейно-алгебраического подхода является частая смена плотности фронта и неоптимальность стандартного направления обхода (\textit{push-интенсивный BFS}). Для повышения производительности на таких топологиях требуется явное переключение на алгоритм \textit{direction-optimizing BFS} (смена направления умножения при разрастании фронта), что выходит за рамки базовых тестов.
\end{itemize}

Столь существенный разрыв (до~17.12~раза на графе \texttt{road\_usa}) обусловлен двумя ключевыми факторами:

\begin{itemize}
    \item \textbf{Издержки на трансформацию данных:} Специфика архитектуры \texttt{BGL} требует промежуточного формирования списка ребер в виде динамического вектора пар объектов \texttt{std::vector<std::pair<int, int>>} и последующей инициализации внутреннего контейнера \texttt{compressed\_sparse\_row\_graph}. Регулярные аллокации памяти в куче процессора для миллионов элементов на каждом запуске создают критическую системную нагрузку, отсутствующую при прямой работе с готовыми статическими структурами \texttt{CSR} в разработанном Си-коде.
    \item \textbf{Локальность кэш-памяти:} Принудительное использование компактного 32-битного знакового типа данных \texttt{int} для хранения индексов вершин и смещений минимизирует footprint структур в памяти, обеспечивая оптимальную плотность данных в кэш-памяти процессора уровней \texttt{L1/L2} и снижая количество промахов кэша по сравнению с обобщенными объектными абстракциями C++.
\end{itemize}

Аномально высокий коэффициент ускорения на графе \texttt{road\_usa} (17.12~раза) напрямую объясняется спецификой его топологии. Дорожная сеть США обладает колоссальным топологическим диаметром при крайне низкой средней степени связности вершин. В этих условиях алгоритм \texttt{BFS} вынужден выполнять тысячи последовательных итераций с обходом микро-фронтов. Шаблонный механизм \foreignlanguage{english}{BFS visitors} библиотеки \texttt{Boost BGL} на каждой итерации генерирует цепочки вызовов функций обратной связи для фиксации предков. На протяженных цепочечных структурах суммарные накладные расходы на обеспечение работы этих C++ абстракций накапливаются экспоненциально, в то время как разработанный низкоуровневый Си-код осуществляет прямое линейное чтение списков смежности \texttt{CSR} через базовые указатели, демонстрируя максимальную аппаратную эффективность.

\section{Заключение}

В ходе выполнения настоящей работы был проведен комплексный сравнительный анализ производительности алгоритмов обхода в ширину (BFS) в зависимости от структурной связности и топологии входных данных. Получены следующие основные результаты:

\begin{itemize}
    \item На языке C (стандарт C11) реализованы четыре авторские модификации алгоритма обхода в ширину: две классические теоретико-графовые версии на структурах \texttt{CSR} (одиночный и мультиресурсный поиск) и две линейно-алгебраические версии на базе матрично-векторных операций библиотеки \texttt{SuiteSparse:GraphBLAS}.
    \item Спроектирована модульная инфраструктура автоматизированного тестирования на стыке языков C и C++, обеспечивающая перекрёстную валидацию результатов, интеграцию внешних библиотек и верификацию топологических инвариантов дерева предков для контроля логической корректности вычислений.
    \item Проведены детальные экспериментальные замеры времени выполнения обхода на семи крупномасштабных разреженных графах различной связности из коллекции \foreignlanguage{english}{SuiteSparse Matrix Collection}.
    \item \textbf{Аналитически обоснованы границы применимости исследуемых подходов в зависимости от топологии графов}. Установлено, что линейно-алгебраический подход на базе \texttt{GraphBLAS} наиболее эффективен на безмасштабных сетях с малым диаметром (\texttt{com-Orkut}, \texttt{soc-LiveJournal1}), где высокая плотность волнового фронта позволяет внутренним параллельным механизмам библиотеки нивелировать накладные расходы на диспетчеризацию операций (достигнуто ускорение до~3,91~раза). Напротив, на сильно разреженных протяженных структурах дорожных сетей (\texttt{road\_usa}, \texttt{roadNet-CA}) последовательный обход имеет преимущество при одиночном запуске из-за отсутствия издержек на динамическое управление разреженными векторами. При этом показано, что в сценариях мультипоиска внутренние алгоритмы редукции \texttt{GraphBLAS} позволяют значительно сгладить этот разрыв производительности.
    \item Выполнено бенчмаркинг-сравнение разработанных решений с шаблонной C++ реализацией из академической библиотеки \texttt{Boost Graph Library} (BGL). Экспериментально подтверждено, что за счёт прямой работы с памятью в рамках модели \texttt{CSR}, использования компактных типов данных и отсутствия избыточных объектных абстракций и итераторов, созданная низкоуровневая кодовая база на языке C демонстрирует превосходство по времени выполнения над эталоном BGL на всех исследованных типах топологий.
\end{itemize}
