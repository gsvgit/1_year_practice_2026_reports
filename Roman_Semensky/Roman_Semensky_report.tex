\section{Введение}
Работа выполнялась в рамках учебной практики и проекта по реализации примитивов разреженной линейной алгебры. Разреженная матрица содержит преимущественно нулевые элементы. В формате разреженного хранения записываются ненулевые элементы и их индексы.

В проекте создана собственная реализация формата COO (Coordinate List~--- список координат) на языке~C. Её производительность сравнивалась с CSparse~--- библиотекой для операций над разреженными матрицами, входящей в SuiteSparse~\cite{davis2006}. Исходный код реализации и программы экспериментов опубликованы в репозитории проекта\footnote{\url{https://github.com/rmnsmnsk/implementation-of-linear-algebra-primitives}}.

Профилирование использовалось для определения наиболее затратных фаз алгоритмов и выбора направлений их оптимизации.

\section{Цель и задачи работы}
Цель работы~--- реализовать операции умножения для разреженных матриц в формате COO, исследовать их производительность в сравнении с CSparse и определить наиболее затратные действия в собственных алгоритмах.

Для достижения цели были поставлены следующие задачи:
\begin{enumerate}
\item реализовать умножение двух COO-матриц;
\item реализовать умножение COO-матрицы на разреженный вектор без его преобразования в плотный массив;
\item подготовить матрицы разного размера из SuiteSparse Matrix Collection;
\item измерить время двух операций для COO и CSparse по единой методике;
\item измерить затраты времени по фазам собственных алгоритмов.
\end{enumerate}

\section{Описание решения}
В формате COO для каждого ненулевого элемента хранятся индекс строки, индекс столбца и значение. Эти данные размещаются в трёх одномерных массивах. Для упорядочивания элементов по индексам строк и столбцов используется функция \texttt{qsort}.

При умножении матриц для второго сомножителя строится индекс строк. Значения одной строки результата накапливаются во временном массиве по индексам столбцов. В базовой версии после обработки каждой строки просматривался весь временный массив. В окончательной версии битовая карта разделена на 64-битные блоки, а индексы изменённых блоков сохраняются отдельно. Если изменённых блоков мало, обрабатываются только они; иначе просматривается вся битовая карта. Массивы результата расширяются по мере заполнения.

Разреженный вектор представляется как COO-матрица размера $n\times1$. В базовой версии значение вектора находилось двоичным поиском по его ненулевым элементам. Замена двоичного поиска хеш-таблицей сократила стоимость одного поиска, но сохранила проход по всем ненулевым элементам матрицы. В окончательной версии для матрицы предварительно строится вспомогательный индекс по занятым столбцам. При умножении перебираются ненулевые элементы вектора и обрабатываются только соответствующие столбцы матрицы. Матрица и вектор продолжают храниться в формате COO; плотный вектор из $n$ значений не создаётся.

Для сравнения CSparse получает те же матрицы в формате CSC (Compressed Sparse Column~--- сжатое хранение по столбцам). Входные представления и вспомогательный индекс COO подготавливаются до замеров; измеряется только операция умножения. Время построения индекса измеряется отдельно. Результаты относятся к двум конкретным реализациям и не используются для вывода о форматах COO и CSC в целом.

Измерялись $A\times A$ и $A\times x$. Вектор $x$ имел тот же размер, что и число столбцов $A$, а доля его ненулевых элементов составляла 10\%, поэтому вектор оставался разреженным. Перед созданием векторов генератор псевдослучайных чисел инициализировался фиксированным значением 42. Перед замерами выполнялись три прогревочных вызова. Затем проводились 15 измерительных серий. Число операций в серии увеличивалось, пока её общая длительность не достигала 100~мс; время серии делилось на число выполненных операций.

Для результатов серии $t_1,\ldots,t_{15}$ вычислялись выборочное среднее
\[
\overline{t}=\frac{1}{15}\sum_{i=1}^{15}t_i
\]
и выборочное стандартное отклонение
\[
s=\sqrt{\frac{1}{14}\sum_{i=1}^{15}(t_i-\overline{t})^2}.
\]
Так как дисперсия времени заранее неизвестна, для среднего указывался 95\%-й доверительный интервал по распределению Стьюдента:
\[
\overline{t}\pm t_{0{,}975;14}\frac{s}{\sqrt{15}}, \qquad t_{0{,}975;14}=2{,}145.
\]
В таблицах результат записан как среднее плюс-минус половина ширины этого интервала. Время и половина ширины интервала округлялись до двух знаков после запятой в указанной единице измерения. Проценты и отношения времён также округлялись до двух знаков после запятой. Для результатов меньше 1~мкс используются наносекунды, для результатов меньше 1~мс~--- микросекунды, для остальных~--- миллисекунды. Единица указана в каждой строке таблиц финального сравнения. Для сравнения COO и CSparse также вычислялись попарные разности результатов серий $d_i=t_i^{\mathrm{COO}}-t_i^{\mathrm{CSparse}}$ и доверительный интервал для их среднего. Положительный интервал, не содержащий ноль, означает меньшее время CSparse; отрицательный~--- меньшее время COO.

\subsection{Профилирование и оптимизация COO-реализации}
Цель профилирования~--- найти действия, ограничивающие применение реализации к матрицам с миллионами строк. Поэтому на всех этапах профилирования использовались три крупнейшие матрицы из табл.~\ref{tab:matrices}. Отдельно измерялись подготовка рабочих структур, накопление произведений, обработка временного массива и поиск значения разреженного вектора. Профильная сборка использовала \texttt{-O3}\footnote{Программа и исходные результаты профилирования: \url{https://github.com/rmnsmnsk/implementation-of-linear-algebra-primitives/blob/main/src/profile.c}, \url{https://github.com/rmnsmnsk/implementation-of-linear-algebra-primitives/blob/main/profiling_results.csv}.}.

В базовой версии $A\times A$ после вычисления каждой строки просматривался временный массив длиной, равной числу столбцов. Один вызов на каждой из трёх матриц не завершился за 60 секунд. После замены полного просмотра обработкой только затронутых блоков битовой карты среднее время окончательной версии составило от 196{,}73 до 406{,}11~мс.

Для $A\times x$ первоначально двоичный поиск значения вектора был заменён хеш-таблицей. Последующее профилирование показало, что при этом сохраняется обход всех ненулевых элементов матрицы. Поэтому для окончательной версии был добавлен индекс по столбцам, позволяющий начинать обход с ненулевых элементов вектора. В табл.~\ref{tab:optimization} для $A\times x$ сопоставлены версия с хеш-таблицей и окончательная индексированная версия\footnote{Данные сравнения: \url{https://github.com/rmnsmnsk/implementation-of-linear-algebra-primitives/blob/main/optimization_results.csv}}.

Полный просмотр временного массива делал время $A\times A$ зависимым от числа строк и столбцов даже при малом NNZ. Обработка только затронутых блоков устранила эту зависимость от всех столбцов и обеспечила завершение операции на миллионных матрицах. Для $A\times x$ переход от обхода всей матрицы к обработке выбранных столбцов сократил среднее время на 67{,}40--74{,}39\%. Для каждой из трёх матриц 95\%-й доверительный интервал средней попарной разности между базовой и окончательной версиями был положительным.

Среднее время построения индекса по столбцам составляло $346{,}81 \pm 2{,}07$~мс на \texttt{roadNet-PA}, $434{,}05 \pm 5{,}34$~мс на \texttt{roadNet-TX} и $657{,}17 \pm 32{,}87$~мс на \texttt{roadNet-CA}. Индекс используется повторно и относительно версии с хеш-таблицей окупался после 9--12 умножений одной матрицы на разреженные векторы.

Обе операции были выполнены на матрицах размером до $1\,971\,281\times1\,971\,281$; результаты совпали с результатами CSparse.

\section{Заключение}
В ходе работы были получены следующие результаты.
\begin{itemize}
\item Реализовано умножение двух COO-матриц.
\item Реализовано умножение COO-матрицы на разреженный вектор без преобразования в плотный массив.
\item Для экспериментов подготовлены 12 матриц размером от $62\times62$ до $1\,971\,281\times1\,971\,281$ из SuiteSparse Matrix Collection. Все результаты операций совпали с результатами CSparse.
\item Профилирование на трёх миллионных матрицах выявило полный просмотр временного массива при $A\times A$ и просмотр всей матрицы с повторным поиском элементов вектора при $A\times x$. После обработки только затронутых блоков базовое $A\times A$, не завершавшееся за 60 секунд, стало выполняться в среднем за 0{,}20--0{,}41 секунды. После построения индекса столбцов среднее время $A\times x$ уменьшилось на 67{,}40--74{,}39\%; затраты на построение индекса компенсировались после 9--12 умножений.
\item В финальном сравнении CSparse имела меньшее среднее время в 23 из 24 случаев. COO-реализация показала меньшее среднее время только на \texttt{football} при $A\times A$. На крупных матрицах отношение средних времён COO и CSparse составило 2{,}05--2{,}34 для $A\times A$ и 1{,}03--2{,}18 для $A\times x$. Во всех сравнениях 95\%-й доверительный интервал средней попарной разности не содержал ноль. Вывод относится к двум исследованным реализациям.
\end{itemize}
